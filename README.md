# LAN Transfer: документация

`lan_transfer.py` передаёт файлы и папки между компьютерами в локальной сети. Один файл, только стандартная библиотека Python (нужен Python 3.8 или новее), ничего устанавливать не нужно.

Скрипт можно использовать тремя способами:

1. **Интерактивное меню**: `python lan_transfer.py`
2. **Командная строка**: `python lan_transfer.py send ...`
3. **Библиотека**: `import lan_transfer as lt`

## 1. Возможности

| Возможность | Описание |
|---|---|
| Автопоиск | Устройства находят друг друга сами (UDP-broadcast), вводить IP не нужно |
| Ручной IP | Если автопоиск не работает (разные подсети, VPN), можно указать IP |
| ID и имена | У каждого устройства постоянный ID (`dev_...`) и изменяемое имя |
| Одинаковые имена | Различаются по ID: `Ноутбук #a1b2` и `Ноутбук #c3d4` |
| Подтверждение | Получатель решает, принять ли подключение, и выбирает папку сохранения |
| Манифест | У обеих сторон хранится файл с описанием передачи и списком блоков |
| Докачка | После обрыва передача продолжается с того места, где остановилась |
| Передача изменений | Если у получателя уже есть старая версия файла, по сети идут только изменённые куски |
| Целостность | Каждый блок проверяется хэшем |
| Папки | Передаются вместе с вложенными папками, включая пустые |
| Утилита и библиотека | Командная строка и функции для импорта |

## 2. Быстрый старт

Запустите скрипт на обоих компьютерах.

**Компьютер Б (получатель):**
```
python lan_transfer.py
```
Выберите `2. Принять`.

**Компьютер А (отправитель):**
```
python lan_transfer.py
```
Выберите `1. Отправить`, затем номер устройства из списка. На компьютере Б появится вопрос «Принять подключение?» (ответьте `y` и укажите папку). После этого на компьютере А введите путь к файлу или папке, и начнётся передача.

То же самое одной командой в каждом окне:
```
python lan_transfer.py receive --dir D:\inbox --yes --once
python lan_transfer.py send C:\photos --to "Ноутбук"
```

## 3. Сеть, порты и брандмауэр

| Порт | Протокол | Для чего |
|---|---|---|
| 9001 | UDP | Автопоиск. Каждое устройство каждые 2 секунды объявляет себя |
| 9000 | TCP | Сама передача. Открывается только в режиме приёма |

**Подсеть.** Широковещательные пакеты не проходят через роутеры. Устройства автоматически видят друг друга, только если они в одной подсети (например, оба подключены к одному роутеру). Для разных подсетей, гостевого Wi-Fi или VPN используйте ручной IP (`--ip` или клавиша `m` в меню).

**Брандмауэр.** Если Windows спросит про доступ, разрешите для частных сетей. Вручную (командная строка от администратора):
```
netsh advfirewall firewall add rule name="LAN Transfer" dir=in action=allow protocol=TCP localport=9000
netsh advfirewall firewall add rule name="LAN Transfer UDP" dir=in action=allow protocol=UDP localport=9001
```

**Занятый порт.** Если TCP-порт 9000 занят, режим приёма автоматически выбирает свободный порт и объявляет его в автопоиске. При подключении по IP тогда нужно указывать порт: `--ip 192.168.1.5:54321`.

## 4. Интерактивное меню

Запуск без аргументов: `python lan_transfer.py`.

| Пункт | Что делает |
|---|---|
| 1. Отправить | Показывает устройства. Выбор: номер, `r` (обновить), `m` (ввести IP), `q` (назад). После выбора ждёт подтверждения получателя, затем спрашивает путь к файлу или папке |
| 2. Принять | Включает режим приёма. На каждый входящий запрос спрашивает «Принять?» и папку сохранения. Выход в меню: Ctrl+C |
| 3. Незавершённые передачи | Список прерванных передач. Для отправки можно выбрать и продолжить. Для приёма нужно включить «Принять» и дождаться отправителя |
| 4. Устройства в сети | Устройства, которые сейчас видны, и известные, которых сейчас нет |
| 5. Сменить имя | Меняет имя. ID остаётся прежним |
| 0. Выход | Выход |

В списке устройств возле нового устройства стоит пометка `(новое)`, а статус показывает, принимает ли оно сейчас файлы. Выбрать для отправки можно только устройство в режиме приёма.

Ctrl+C во время передачи останавливает её, прогресс сохраняется.

## 5. Командная строка

```
python lan_transfer.py [--home ПАПКА] <команда> [параметры]
```

`--home` задаёт папку для `device.json` и манифестов. Без него используется папка со скриптом (или путь из переменной окружения `LAN_TRANSFER_HOME`). Это позволяет запускать несколько «устройств» на одном компьютере.

### `devices` — показать устройства

```
python lan_transfer.py devices [--wait 3] [--json]
```

| Параметр | Описание |
|---|---|
| `--wait N` | Сколько секунд слушать сеть (по умолчанию 3) |
| `--json` | Вывод в формате JSON |

### `send` — отправить

```
python lan_transfer.py send ПУТЬ (--to ИМЯ | --ip АДРЕС) [--wait 5] [--timeout 120]
```

| Параметр | Описание |
|---|---|
| `ПУТЬ` | Файл или папка |
| `--to` | Имя, метка (`Имя #abcd`) или ID устройства |
| `--ip` | IP получателя, можно с портом: `192.168.1.5:9000` |
| `--wait N` | Сколько секунд искать устройство при `--to` (по умолчанию 5) |
| `--timeout N` | Сколько секунд ждать подтверждения получателя (по умолчанию 120) |

Нужно указать либо `--to`, либо `--ip` (не оба сразу). Если несколько устройств с одинаковым именем, скрипт сообщит об этом и покажет метки и ID, из которых можно выбрать.

### `receive` — принимать

```
python lan_transfer.py receive [--dir ПАПКА] [--yes] [--from ИМЯ] [--once] [--timeout N]
```

| Параметр | Описание |
|---|---|
| `--dir` | Папка сохранения. По умолчанию `received` рядом со скриптом |
| `--yes` | Принимать без вопросов |
| `--from` | Принимать только от устройства с таким именем или ID |
| `--once` | Принять одну передачу и выйти |
| `--timeout N` | Выйти, если за N секунд никто не подключился |

Без `--yes` скрипт спрашивает подтверждение в консоли.

### Остальные команды

| Команда | Что делает |
|---|---|
| `name` | Показывает имя устройства |
| `name НОВОЕ_ИМЯ` | Меняет имя |
| `id` | Показывает ID устройства |
| `unfinished` | Список незавершённых передач |

### Коды возврата

| Код | Значение |
|---|---|
| 0 | Успех |
| 1 | Передача не завершена или произошла ошибка |
| 2 | `send` без `--to` и `--ip` |
| 130 | Прервано через Ctrl+C |

## 6. Использование как библиотеки

```python
import lan_transfer as lt
```

### `discover(timeout=3.0, device=None, discovery=None)`

Слушает сеть `timeout` секунд и возвращает список устройств:

```python
for d in lt.discover():
    print(d["label"], d["id"], d["ip"], d["receiving"])
```

Поля каждого элемента:

| Поле | Описание |
|---|---|
| `id` | ID устройства |
| `name` | Имя |
| `label` | Имя для показа. Если имена повторяются, содержит суффикс `#abcd` |
| `ip`, `port` | Адрес для подключения |
| `receiving` | `True`, если устройство сейчас в режиме приёма |

### `send(source, to=None, ip=None, *, ...)`

Отправляет файл или папку. Нужно указать `to` или `ip`, иначе будет `ValueError`.

```python
res = lt.send(r"C:\photos", to="Ноутбук")
res = lt.send(r"C:\photos", ip="192.168.1.5")
res = lt.send(r"C:\photos", ip="192.168.1.5:54321")
```

| Параметр | По умолчанию | Описание |
|---|---|---|
| `source` | — | Путь к файлу или папке |
| `to` | `None` | Имя, метка или ID устройства (поиск автоматический) |
| `ip` | `None` | IP, можно с портом |
| `device` | текущее | Объект `Device` (если нужно другое устройство) |
| `discovery` | `None` | Готовый объект `Discovery`. Если не задан, создаётся временный |
| `discover_timeout` | `5.0` | Сколько секунд искать устройство при `to=` |
| `confirm_timeout` | `120.0` | Сколько ждать подтверждения получателя |
| `log` | `print` | Функция для сообщений. `None` отключает вывод |
| `on_progress` | `None` | Функция, получающая данные о прогрессе (см. ниже) |
| `show_progress` | `True` | Показывать строку прогресса в консоли |

**Возвращает словарь:**

| Ключ | Описание |
|---|---|
| `ok` | `True`, если передача завершена и проверена получателем |
| `status` | `complete`, `rejected`, `interrupted` или `error` |
| `message` | Описание результата |
| `transfer_id` | ID передачи |
| `peer` | `{"id": ..., "name": ...}` получателя |
| `chunks_done`, `total_chunks` | Сколько блоков принято из скольки |
| `wire_bytes` | Сколько байт реально ушло по сети (данные файлов) |
| `reused_bytes` | Сколько байт не пришлось отправлять, потому что они уже были у получателя |

Статусы: `complete`: успешно; `rejected`: получатель отклонил; `interrupted`: оборвалась на середине (можно продолжить повторным вызовом); `error`: не удалось подключиться, путь не найден и т. п.

### `receive(save_dir=None, *, ...)`

Включает режим приёма и ждёт отправителей. Это то же самое, что пункт «Принять» в меню.

```python
results = lt.receive(r"D:\inbox", auto_accept=True, once=True)
```

| Параметр | По умолчанию | Описание |
|---|---|---|
| `save_dir` | `received` | Папка, куда сохранять принятое |
| `auto_accept` | `False` | Принимать подключения без вопросов. Иначе вопрос в консоли |
| `only_from` | `None` | Принимать только от этого имени или ID (строка или список) |
| `once` | `False` | Принять одну передачу и вернуться. Иначе ждёт, пока не остановят |
| `timeout` | `None` | Вернуться, если за столько секунд никто не подключился |
| `accept_cb` | `None` | Своя функция подтверждения (см. ниже) |
| `stop_event` | `None` | `threading.Event`; когда он выставлен, приём завершается |
| `announce` | `True` | Объявлять устройство в автопоиске. `False`, если подключаются только по IP |
| `server` | `None` | Готовый слушающий сокет (например, из `open_server()`) |
| `log`, `on_progress`, `show_progress` | как у `send` | |

**Возвращает** список результатов, по одному на каждую обработанную передачу, в том же формате, что у `send`. Дополнительно есть поле `save_dir`.

**Своя логика подтверждения.** `accept_cb(info)` получает словарь `{"id", "name", "ip", "known"}`. Верните путь к папке, чтобы принять, или `None`, чтобы отклонить:

```python
def my_rule(info):
    if info["name"] == "Ноутбук":
        return r"D:\from_laptop"
    return None          # остальных отклонять

lt.receive(accept_cb=my_rule)
```

**Остановка из другого потока:**
```python
import threading
stop = threading.Event()
threading.Thread(target=lt.receive, kwargs=dict(
    save_dir="inbox", auto_accept=True, stop_event=stop, log=None)).start()
...
stop.set()
```

### Прогресс: `on_progress`

Функция вызывается примерно 3 раза в секунду со словарём:

| Ключ | Описание |
|---|---|
| `label` | `Отправка` или `Приём` |
| `bytes_done`, `bytes_total` | Сколько байт готово из скольки |
| `chunks_done`, `chunks_total` | Сколько блоков готово из скольки |
| `speed` | Скорость, байт в секунду |

```python
lt.send("data", ip="192.168.1.5",
        on_progress=lambda p: print(p["bytes_done"] * 100 // p["bytes_total"], "%"),
        show_progress=False)
```

### Прочие функции

| Функция | Описание |
|---|---|
| `get_name()` / `set_name(name)` | Имя устройства |
| `get_id()` | ID устройства |
| `unfinished()` | Список манифестов незавершённых передач |
| `get_device(home=None)` | Объект `Device`. С `home` создаёт отдельное устройство со своей папкой данных |

Классы `Device` (хранение ID и имени), `Discovery` (автопоиск) и `Manifest` (манифест передачи) тоже доступны для импорта, если нужен более тонкий контроль.

## 7. Устройства: ID и имена

**ID** создаётся один раз при первом запуске в формате `dev_` и 24 шестнадцатеричных символа, например `dev_5058f6c1419aadafd42c4547`. Он не меняется и однозначно определяет устройство.

**Имя** по умолчанию совпадает с именем компьютера. Его можно менять в любой момент (меню, `name`, `set_name`). Имя обрезается до 32 символов, непечатаемые символы удаляются.

**Одинаковые имена.** Если в сети два устройства с одним именем (без учёта регистра), в списках они показываются с суффиксом из последних 4 символов ID: `Ноутбук #a1b2`. Выбирать их можно по этой метке или по полному ID.

**Известные устройства.** Все увиденные устройства сохраняются в `device.json` (имя и последний IP). Устройства, которых ещё не было в списке, помечаются как «новое» при запросе на подключение.

## 8. Файлы, которые создаёт скрипт

Папка данных: рядом со скриптом, либо путь из `--home`, либо из переменной `LAN_TRANSFER_HOME`.

```
device.json                  ID, имя, известные устройства
manifests/                   манифесты передач
received/                    папка приёма по умолчанию
```

### `device.json`

```json
{
  "id": "dev_5058f6c1419aadafd42c4547",
  "name": "Ноутбук",
  "known_peers": {
    "dev_24d5f1ab89cb50b9eb7cd2d7": {
      "name": "ПК",
      "last_ip": "192.168.1.20",
      "last_seen": "2026-10-03T12:00:00+05:00"
    }
  }
}
```

### Манифесты: `manifests/<id_передачи>_<роль>.json`

Роль: `sender` (у отправителя) или `receiver` (у получателя). Обе стороны хранят один и тот же набор сведений.

| Поле | Описание |
|---|---|
| `transfer_id` | ID передачи (`tr_...`) |
| `role` | `sender` или `receiver` |
| `status` | `in_progress`, `complete` или `superseded` (заменена новой версией) |
| `sender`, `receiver` | ID и имя сторон |
| `source_path` | Путь к файлу или папке на стороне отправителя |
| `save_dir` | Папка сохранения на стороне получателя |
| `chunk_size` | Размер блока |
| `dirs` | Список папок (включая пустые) |
| `total_size`, `total_chunks`, `chunks_done` | Общий размер и прогресс |
| `files` | Список файлов, у каждого `path`, `size`, `mtime_ns` и список блоков |

Каждый блок: `{"idx": 0, "offset": 0, "size": 4194304, "done": true}`.

### Временные файлы у получателя

| Файл | Значение |
|---|---|
| `имя.part` | Файл, который ещё принимается. После проверки переименовывается в `имя` |
| `имя.basis` | Старая недокачанная версия, которая используется для сравнения. Удаляется после завершения |

## 9. Как работает передача

1. **Подключение.** Отправитель соединяется с получателем по TCP и отправляет `hello` со своим ID и именем.
2. **Подтверждение.** Получатель решает, принять ли. Если да, он выбирает папку и отвечает `accept` со своим ID, именем и папкой. Отправитель ждёт до 120 секунд.
3. **Выбор файлов.** После подтверждения отправитель выбирает файл или папку. При выборе папки передаётся и сама папка (получатель увидит `папка/файлы`), и все вложенные, включая пустые.
4. **Предложение.** Отправитель присылает список файлов (путь, размер, время изменения), список папок и ID передачи. ID вычисляется из ID обеих сторон, пути источника, папок и файлов.
5. **Готовность.** Получатель создаёт или находит манифест, сверяет его с файлами на диске и сообщает, какие блоки у него уже есть.
6. **Передача блоков.** Файлы режутся на блоки по 4 МБ. Отправитель шлёт только недостающие блоки. Получатель проверяет хэш каждого блока и записывает его в `.part`.
7. **Завершение.** Отправитель сообщает `done`. Получатель проверяет, что получено всё, переименовывает `.part` в итоговые файлы и отвечает `complete`. Только после этого передача считается успешной на обеих сторонах.

Манифесты сохраняются каждые 16 блоков, при остановке и при ошибках.

## 10. Докачка

Если передача прервалась (сеть пропала, Ctrl+C, выключили компьютер), просто повторите отправку той же папки или файла тому же получателю. Скрипт продолжит с места остановки:

- ID передачи вычисляется из тех же данных, поэтому манифесты находятся автоматически;
- получатель сообщает, какие блоки у него реально записаны, и отправитель шлёт только остальные;
- манифест получателя сверяется с файлами на диске: если `.part` пропал, этот файл считается не принятым.

Прерванные передачи видны в пункте меню 3 или командой `unfinished`. Продолжить отправку можно прямо из меню.

Если за время паузы файл изменился, ID передачи будет другим. Прежняя передача пометится как `superseded`, но уже принятые данные не пропадут: недокачанная старая версия станет основой для сравнения (см. следующий раздел).

---

## 11. Передача только изменений

Если у получателя в папке сохранения уже есть файл с таким же путём (старая версия или недокачанная часть), по сети отправляются только отличия.

**Идея.** Получатель режет свою старую версию на блоки и присылает их «отпечатки». Отправитель двигает окно по новой версии файла по одному байту и ищет блоки, которые у получателя уже есть. Позиция не важна: если в середину вставили текст, остальные блоки всё равно находятся.

Простой пример: было `привет`, стало `пират`. Совпавшие куски не пересылаются, получатель берёт их из своего старого файла, а пересылаются только новые байты между ними.

**Как устроено:**

- Блок сравнения выбирается по размеру базового файла: степень двойки от 2 КБ до 128 КБ, близкая к корню из размера.
- Быстрая проверка: контрольная сумма Adler-32, которую можно пересчитывать при сдвиге окна на 1 байт без повторного чтения блока.
- Точная проверка: хэш BLAKE2b (8 байт) для каждого найденного совпадения.
- Сравнение выполняется внутри каждого блока передачи (4 МБ). Получатель собирает блок из кусков своей старой версии и новых байт, затем проверяет итоговый хэш блока.

**Ограничения и оптимизации:**

- Файлы меньше 8 КБ отправляются целиком.
- Если после первых 8 МБ совпадает меньше 10%, сравнение отключается для этого файла и остаток идёт целиком (поиск на чистом Python медленный, около 1 МБ/с).
- Совпадения не могут пересекать границу блока в 4 МБ.

Результат `send` показывает эффект: `wire_bytes` (сколько ушло по сети) и `reused_bytes` (сколько уже было у получателя).

## 12. Протокол

Каждое сообщение: 4 байта длины (big-endian) и JSON. После `chunk`, `delta` и `sig` следуют сырые байты. Подключения обрабатываются по одному.

| Сообщение | Направление | Содержание |
|---|---|---|
| `hello` | отправитель → получатель | ID, имя отправителя, `to_id` (или `null` при подключении по IP) |
| `accept` / `reject` | получатель → отправитель | При `accept`: ID, имя, папка сохранения |
| `offer` | отправитель → получатель | ID передачи, путь источника, размер блока, файлы, папки |
| `ready` | получатель → отправитель | Список уже имеющихся блоков по файлам |
| `sigreq` / `sig` | оба | Запрос и ответ с отпечатками старой версии файла |
| `chunk` | отправитель → получатель | Блок целиком: индекс файла и блока, размер, хэш, затем данные |
| `delta` | отправитель → получатель | Блок в виде команд «взять из базы» и «вставить новые байты» |
| `done` / `complete` | отправитель / получатель | Конец передачи и подтверждение проверки |
| `error`, `bye` | любой | Ошибка или досрочное завершение сеанса |

Автопоиск использует UDP-сообщения JSON: `{app, v, id, name, port, receiving}`.

## 13. Безопасность

Что есть:

- **Подтверждение получателя.** Ничего не принимается без согласия (кроме `auto_accept`).
- **Защита путей.** Пути из сети проверяются: `..`, абсолютные пути и выход за папку сохранения отклоняются.
- **Проверка целостности** каждого блока и размера итоговых файлов.
- **Очистка имён** от непечатаемых символов.

Чего нет:

- **Шифрования нет.** Данные идут по сети открытым текстом. Используйте только в доверенной сети.
- **Аутентификации нет.** Любой в сети может запросить передачу. ID устройства не защищён паролем, его можно подделать. С `auto_accept=True` без `only_from` принимается всё от любого. `only_from` сверяет имя или ID, которые устройство сообщает само.

## 14. Настройки (константы)

Находятся в начале файла.

| Константа | Значение | Описание |
|---|---|---|
| `TCP_PORT` | 9000 | Порт передачи |
| `DISCOVERY_PORT` | 9001 | Порт автопоиска |
| `CHUNK_SIZE` | 4 МБ | Размер блока |
| `BROADCAST_INTERVAL` | 2 с | Как часто устройство объявляет себя |
| `PEER_TTL` | 8 с | Через сколько секунд молчания устройство пропадает из списка |
| `IDLE_TIMEOUT` | 30 с | Таймаут бездействия во время передачи |
| `CONFIRM_TIMEOUT` | 120 с | Сколько отправитель ждёт подтверждения |
| `OFFER_TIMEOUT` | 600 с | Сколько получатель ждёт, пока отправитель выберет файлы |
| `SAVE_EVERY` | 16 | Как часто сохранять манифест (в блоках) |
| `MIN_DELTA_SIZE` | 8 КБ | Меньшие файлы отправляются целиком |
| `DELTA_PROBE` | 8 МБ | Сколько данных пробовать, прежде чем отказаться от сравнения |

Значения можно менять и из кода: `lt.CHUNK_SIZE = 1024 * 1024`. Получатель принимает размер блока от отправителя в пределах от 64 КБ до 64 МБ.

## 15. Ограничения

- Только IPv4 и только локальная сеть: нет обхода NAT и выхода в интернет.
- Автопоиск работает в пределах одной подсети (для остальных случаев есть ручной IP).
- Шифрования и паролей нет (см. раздел 13).
- Сохраняются только содержимое и структура. Время изменения, права доступа и атрибуты файлов не переносятся.
- Символические ссылки на папки пропускаются.
- Одновременно обрабатывается одна передача на одного получателя.
- Если файл изменился во время передачи, она прервётся. Повторный запуск начнёт новую передачу с использованием уже принятых данных.
- Если в папке получателя лежит другой файл с тем же путём, он будет использован как база для сравнения и в конце заменён.
- Сравнение версий на чистом Python работает медленно на сильно изменённых файлах (см. раздел 11).

## 16. Решение проблем

| Проблема | Что делать |
|---|---|
| Устройство не видно в списке | Проверьте, что оба в одной сети. Откройте UDP 9001 в брандмауэре. Убедитесь, что устройство не заблокировано роутером (изоляция клиентов в Wi-Fi). Подключитесь по IP |
| Видно, но «не в режиме приёма» | На втором компьютере выберите «2. Принять» или запустите `receive` |
| Не удаётся подключиться | Откройте TCP 9000 в брандмауэре. Проверьте IP. Если порт 9000 был занят, укажите порт: `--ip АДРЕС:ПОРТ` (порт виден в сообщении «Режим приёма включён (порт ...)») |
| «Автопоиск не работает: порт UDP 9001 занят» | Порт использует другая программа. Подключайтесь по IP |
| Получатель долго не отвечает | Подтверждение ждёт ответа в консоли получателя (до 120 секунд по умолчанию) |
| «ID получателя не совпал» | Адрес теперь принадлежит другому устройству (сменился IP). Найдите устройство заново |
| Передача началась заново | Файл или папка изменились, либо источник другой. Старые данные всё равно будут использованы для сравнения |
| `устройство «...» не найдено в сети` | Увеличьте `--wait` или проверьте, что получатель в режиме приёма |
| `имя «...» неоднозначно` | Укажите метку (`Имя #abcd`) или полный ID |
| Остались файлы `.part` или `.basis` | Это незавершённая передача. Повторите её, чтобы закончить. Если она больше не нужна, файлы можно удалить вручную |
| Сбросить ID и имя | Удалите `device.json`. При следующем запуске создастся новый ID |
